# GUIDE DE PUSH DANS KARATAKA GAME

## 1️⃣ Vérifier si Git est installé
Ouvrez un Terminal et lancez la commande :
```bash
git --version
```

Dans le cas contraire, installez-le :
```bash
sudo apt install git -y
```
ou
```bash
sudo dnf install git -y
```

## 2️⃣ Initialiser git dans votre machine
Configurez votre nom et votre email :
```bash
git config --global user.name "ton_nom_github"
git config --global user.email "your.email@example.com"
```

## 3️⃣ Choisissez une des méthodes de contrôle suivantes :
### Méthode A : HTTPS (avec une gpg key) :
1. **Vérifiez si le tool de génération d'une gpg key est installé**

    Si **gnupg** est installé
    ```bash
        gpg --full-generate-key
    ```
    Dans le cas contraire, installez-le :
    ```bash
    sudo apt install gnupg -y
    ```
    ou
    ```bash
    sudo dnf install gnupg
    ```
2. **Générez votre gpg key**
    ```bash
    gpg --full-generate-key
    ```
    Puis remplis les informations :
    
    - Please select what kind of key you want : choix :   **1**
    - What keysize do you want ? :  **4096**
    - Please specify how long the key is valid :  **0**
    - Is this correct ? : **yes**
    - GnuPG needs to construct a user ID to identify your key.
        - Real name : **votre_nom_github**
        - Email adress : **votre_email_rattaché_à_votre_compte_github**
        - Comment : **optionnel** (vous pouvez laisser vide et taper sur Enter)
    - You selected this USER-ID: "nom_github (comment) <votre_email@gmail.com>" : **o**

3. **Ajoutez votre GPG key dans Github**
    - Allez dans la page de [SSH and GPG keys](https://github.com/settings/gpg/new) dans github
    - Suivez les étapes suivantes : 
    ```mermaid
    flowchart LR
        Step1[**New GPG key**]--> Step2[**Title**]--> Step3[**Key**]--> Step4[**Add GPG key**]
        style Step1 fill:#38833b, color: #fff
        style Step2 fill:#156b99, color: #fff
        style Step3 fill:#156b99, color: #fff
        style Step4 fill:#4CAF50, color:#fff
    ```
    - Dans l'étape 3 :
        - Trouvez la GPG key générée précédement
            ```bash
            gpg --list-secret-keys --keyid-format=long
             ```
        - Il y aura un résultat comme
            ```bash
            sec   rsa4096/3AA5C34371567BD2 2024-01-15 [SC]
            AB12CD34EF56GH78IJ90KL12MN34OP56QR78ST90
            uid                 [ultimate] Ton Nom <ton.email@exemple.com>
            ```

        - Exportez une public key pour votre GPG
            ```bash
            gpg --armor --export <le chiffre derrière le />
            ```

        - Collez la public key générée dans la section [**Key**](https://github.com/settings/keys) de Github
        
            Elle est de la sorte : 

            ```bash
            -----BEGIN PGP PUBLIC KEY BLOCK-----
                        un long texte
            -----END PGP PUBLIC KEY BLOCK-----
            ```
### Méthode B : SSH (avec une SSH key) :
1. **Vérifiez si le tool de génération est installé**

    Si **ssh-keygen** est installé
    ```bash
    ssh-keygen -v
    ```
    Dans le cas contraire, installez-le :
    ```bash
    sudo apt install openssh-client -y
    ```
    ou
    ```bash
    sudo dnf install openssh-clientis -y
    ```

2. **Générez votre SSH key**
    ```bash
    ssh-keygen -t ed25519 -C "votre_email_rattaché_à_votre_compte_github"
    ```
3. **Exportez une public key pour votre SSH**
    ```bash
    cat ~/.ssh/id_ed25519.pub
    ```

    Elle est de la sorte :
    ```bash
    ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAI... votre_email_rattaché_à_votre_compte_github
    ```  

3. **Ajoutez votre SSH key dans Github**    
    - Allez dans la page [**SSH and GPG keys**](https://github.com/settings/keys) dans Github
    - Suivez les étapes suivantes : 
    ```mermaid
    flowchart LR
        Step1[**New SSH key**]--> Step2[**Title**]--> Step3[**Key**]--> Step4[**Add SSH key**]
        style Step1 fill:#38833b, color: #fff
        style Step2 fill:#156b99, color: #fff
        style Step3 fill:#156b99, color: #fff
        style Step4 fill:#4CAF50, color:#fff
    ```

    - Dans l'étape 3 : 
        - Collez la public key précédente dans la section [**Key**](https://github.com/settings/keys)

4. **Vérifiez si la SSH key marche**
    ```bash
    ssh -T git@github.com
    ```

    Cela affiche :
    ```bash
    Hi votre_nom_github! You've successfully authenticated, but GitHub does not provide shell access
    ```

### **REMARQUES IMPORTANTES**
- **N'utilisez qu'une des méthodes proposées**

- **Il est conseillé, dans le cadre du projet KARATAKA, d'utiliser la méthode SSH car c'est moins cassante que celle avec HTTPS**


## 4️⃣ Clonez le répo de KARATAKA
- ### **Méthode A : HTTPS** 

    ```bash
    git clone https://github.com/Jusinho7/Karataka.git
    ```

- ### **Méthode B : SSH**
    ```bash
    git clone git@github.com:Jusinho7/Karataka.git
    ```

## 5️⃣ Effectuez vos revues / modifications
- Une fois le répo cloné vous pouvez **reviser** le dernier Code du projet ou d'**apporter vos propres modifications**

## 6️⃣ Pushez votre travail
- Après avor fini vos **Modifications** sur le projet. Il est **Interdit** de Pusher directement dans la **main branch** du répo de [**Karataka**](https://github.com/Jusinho7/Karataka#)

- Il faut qu'à chaque **push** vous éffectuez une **Pull Request**

## 7️⃣ Etapes pour faire une **Pull Request** 
- ### Format d'un Pull Request
    ```bash
    <type>/<ticket-ID>-<description courte et claire>
    ```

- ### Types de Pull Request
    - **feat/**
        - feature (nouveauté)
        - Ajout de nouvelle fonctionnalité au code

    - **fix/**
        - fix (correction)
        - Correction d'un Bug dans le code

    - **hotfix** :
        - correction urgente
        - Fix critique à déployer en prod immédiatement (souvent branché depuis main)

    - **chore/** :
        - tâche ménagère
        - Maintenance, config, dépendances (pas de changement de code source)

    - **docs/** :
        - documentation
        - Modifier uniquement des fichiers .d, des commentaires, ...

    - **style/** :
        - style du code
        - Formatage, indentation, espaces (pas de changement de logique)

    - **refactor/** :
        - refactoring
        - Restructuration du code sans changer son comportement externe

    - **test/** :
        - testes
        - Ajout ou modification des **unit test/intégration**

    - **perf/** : 
        - performance
        - Amélioration de la performance du code

- ### Etapes de la Pull Request
    - Effectuez vos modifications (correction, ajout de nouveau script, images, ...)

    - Mettez à jour votre base 
        ```bash
        git checkout main
        git pull origin main 
        ```

    - Créez la branche de travail en respectant le précédent **format**
        ```
        git checkout -b <type>/<Ticket-ID>-<description-courte-et-claire>
        ```

        Exemple : 
        ```bash
        git checkout -b feat/Add-scene-5-to-Karataka
        ```
    - Validez avec un **commit**
        ```git add .
        git commit -m "<type>(Ticket-ID): <description du commit>"
        ```

        Exemple :
        ```bash
            git add .
            git commit -m "feat(Karataka/scripts) : add the 5th scene"
        ```
    - Pusher la branche
        ```bash
        git push origin <nom_de_la_branche>
        ```

        Exemple : 
        ```bash
        git push origin feat/Karataka-add-scene-5
        ```
    - Créez la Pull Request sur **GitHub**
        - Allez dans l'onglet des [**Pull Requests**](https://github.com/Jusinho7/Karataka/pulls) de GitHub

        - Suivez les étapes suivantes : 
            - Cliquez sur le boutton **```New pull request```**

            - Sélectionnez les **branches**
                - **Base branch** (gauche) : la branche de destination : **main**
                - **Compare branch** (droite) : la branche locale que vous venez de Pusher

            - Remplissez le **Title** (Très important)
                Gardez le format **<type>/<ticket-ID>-<description-courte>** précédente

            - Remplissez la **Description**
                Décrivez pourquoi vous avez fait la modification et précisez dans quelle partie du code 
        
            - Cliquez enfin sur le boutton **```Create pull request```**
